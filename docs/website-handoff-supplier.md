# Website in the common text Handoff supplier

The existing HandoffScope and retained AI lifecycle snapshot now accept exactly
TELEGRAM or WEBSITE_WIDGET. They remain keyed by the complete owner, integration,
channel and agent tuple and require an exact trusted managed grant. The existing
agent-proof, revocation receipts, generation fencing and original-dispatch control
evidence ports are reused; no Website lifecycle store or execution path is added.

Enrolled scopes still default empty. This reader extension does not enroll a
Website integration, activate a public mailbox or authorize the UUID-only legacy
Website sessions to receive owner replies. Conversation must provide its common
active grant/proof gates and credential-bound v3 transport first. v1/v2 bytes,
Business capabilities, confirmations, permits and operation ledger stay unchanged.

Lifecycle tests cover Website proof persistence, config removal, failed revoke /
exact retry, replacement-account denial and proof denial while a transition is
pending. The same tests continue to cover Telegram. Voice Handoff is deliberately
not admitted until its media/writer barriers use the common authority contract.
